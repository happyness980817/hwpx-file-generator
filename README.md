# K-브랜드 신청서 도우미

Python + Streamlit으로 회사·상품 정보를 입력하고 필작성 서류 5종을 내려받는 사이트입니다. 접속하면 바로 신청서가 열립니다. 로그인, 문서 비밀번호, 이전 문서 불러오기, 별도 제출 단계는 없습니다.

## 사용 흐름

1. 회사 정보를 직접 입력합니다. 또는 위쪽 **회사명:**에 회사·브랜드를 적고 **신청 내용 자동으로 채우기**를 누릅니다.
2. 필요하면 회사·상품 소개자료를 첨부합니다. **AI에게 요청하기 (선택)**에 지시를 적고 **요청 반영하기**를 누릅니다. 첨부만 있고 요청이 비어 있으면 자료로 빈칸을 보완합니다.
3. 회사·상품·활용계획을 확인하고 수정합니다. 회색 예시는 플레이스홀더이며 실제 문서에 들어가지 않습니다.
4. **신청서 내려받기**를 누르면 필수항목을 검사하고 HWPX 4개와 XLSX 상품리스트 1개를 ZIP으로 내려받습니다. 같은 시점에 신청 정보를 Supabase DB에 저장합니다.

웹검색은 버튼을 눌렀을 때만 실행합니다. 웹검색 결과는 확인된 빈칸만 채우며 기존 입력·선택한 국가·수량을 덮어쓰지 않습니다. 사용자 요청으로 수정할 때도 명시적으로 수정할 항목 이외의 기존 내용은 보존합니다. 출처 정보는 내부 참고용으로 유지하며 화면에 링크 목록을 표시하지 않습니다.

파일 다운로드는 AI를 호출하지 않습니다. 마지막 입력값을 반영해 파일을 생성하고 같은 클릭에서 다운로드를 시작합니다. 브라우저가 자동 다운로드를 차단하면 바로 아래의 작은 **다시 받기** 링크를 사용할 수 있습니다.

입력은 브라우저 접속 세션에서만 편집합니다. 새로고침하면 화면은 초기화될 수 있으며, DB 기록을 사이트에서 불러오는 기능은 없습니다. DB 저장에 실패해도 생성된 파일은 내려받을 수 있고 저장 실패 안내가 표시됩니다. 다시 내려받기를 누르면 같은 기록으로 저장을 재시도합니다.

## 실행

```powershell
uv sync --locked
uv run streamlit run app.py
uv run --locked pytest -q
```

개발 화면: http://127.0.0.1:8501

## Supabase DB 준비

기존 로그인용 테이블이나 저장 자료를 지우지 않습니다. 새 신청 목록은 별도 테이블 **application_submissions**에 저장합니다.

1. 사용할 Supabase 프로젝트를 엽니다.
2. 왼쪽 **SQL Editor → New query**를 선택합니다.
3. 프로젝트의 **supabase/005_application_submissions.sql** 내용을 모두 붙여넣고 **Run**을 누릅니다.
4. **Table Editor**에서 **application_submissions**와 관리자 CSV용 **application_submissions_csv** 뷰가 생성됐는지 확인합니다.
5. 로컬 `.env` 또는 Streamlit Cloud **Settings → Secrets**에 아래 설정을 둡니다.

```toml
OPENAI_API_KEY = "기존 OpenAI API 키"
OPENAI_MODEL = "gpt-6-astra"
OPENAI_REASONING_EFFORT = "high"

SUPABASE_URL = "https://프로젝트ID.supabase.co"
SUPABASE_SECRET_KEY = "해당 프로젝트의 서버용 secret 키"
```

기존 서버용 service_role JWT도 사용할 수 있습니다. 공개용 publishable/anon 키로 저장하지 않습니다. 서버용 키는 Streamlit 서버에서만 사용하며 브라우저·소스 저장소·다운로드 파일에 전달하지 않습니다.

**005 스크립트만 사용합니다.** 기존 001~004 및 로그인/비밀번호 보관 관련 SQL은 이전 구조용이며 이번 화면을 설치할 때 다시 실행하지 않습니다. 현재 앱은 Supabase Auth나 Storage 버킷을 요구하지 않습니다.

## DB에서 목록 내려받기

별도 관리자 사이트를 만들 필요 없이 Supabase의 **SQL Editor**에서 내보낼 수 있습니다.

1. 기존 프로젝트에 접근할 수 있는 **managergoal 구글 계정**으로 Supabase에 로그인합니다.
2. 저장된 [참여기업 목록 · CSV 내려받기](https://supabase.com/dashboard/project/fxcvlugggfxsjastrguy/sql/91cc0756-c23c-4f28-96e4-f1786ca9f598) 조회문을 엽니다.
3. SQL Editor 위쪽 도구 모음의 **Database → Row limit → No limit**를 선택한 뒤 **Run**을 누릅니다. 기본 100행 제한을 그대로 두면 일부 목록만 내려받을 수 있습니다.
4. 조회 결과의 **Export → CSV**를 선택합니다. 저장된 신청 정보가 없으면 내보내기 버튼이 비활성화될 수 있습니다.

저장된 조회문 대신 **SQL Editor → New query**에 아래 내용을 붙여넣어도 됩니다. **Table Editor**의 뷰에서는 목록을 확인하고, CSV 다운로드는 위 SQL 조회 결과에서 진행합니다.

```sql
select *
from public.application_submissions_csv
order by "수정일시(KST)" desc;
```

CSV용 뷰는 회사·대표자·사업자번호·담당자·연락처·상품·국가·활용계획을 열로 보여주며, 수식처럼 시작하는 입력을 엑셀에서 실행하지 않도록 처리합니다. 원본 JSON은 테이블의 **input_data**에 보관합니다. 일반 방문자는 목록을 조회하거나 내려받을 수 없고 관리자 대시보드에서만 관리합니다.

같은 브라우저 세션의 같은 사업자번호는 같은 기록으로 갱신합니다. 내용이 바뀌지 않은 반복 다운로드는 다시 저장하지 않습니다. 다른 사업자번호는 별도 기록을 사용합니다. 새로고침 후에는 새 세션이므로 별도 기록이 될 수 있습니다.

## 저장 범위

신청서 입력값과 첨부 자료 이름·참고 출처를 DB에 저장합니다. 원본 첨부 파일과 생성 HWPX/XLSX 자체는 DB 또는 Storage에 업로드하지 않습니다. 생성 파일은 메모리로 제공하며 생성용 임시 폴더는 처리 후 정리됩니다.

Google Sheets 저장 및 OAuth 설정 코드는 제거했습니다. 기존 구글 스프레드시트의 자료는 변경하거나 삭제하지 않습니다. 이전에 받은 Google 인증 정보는 Git 제외 파일에 남아 있을 수 있으나 앱에서 사용하지 않습니다.

## 기본값과 작성 규칙

- 사용방식: 라벨 (권장), 단일 선택. 수행업체명: 이노프렌즈.
- 신규 국가별 부착 예정수량: 100만장.
- 신청일: 한국 시간 기준 오늘.
- 수출국가: 별첨의 73개국, 가나다순 복수 선택.
- 인증: 별첨의 26종 및 직접 입력.
- 상표: 출원예정·출원중·출원완료·등록예정·등록중·등록완료.
- 국가별 상표·수량·사용방식과 상품별 세부 입력은 각각 보존합니다.

빈 문서 칸은 노란색으로 표시됩니다. 사실로 확인되지 않은 인증·상표·실적·담당자를 만들지 않습니다. 서명·직인·동의·제품사진은 직접 확인해야 합니다.

## AI와 첨부

파일당 10MB, 최대 5개, 합계 25MB. PDF, PNG/JPEG/WebP, DOCX, XLSX, PPTX, HWPX, TXT, CSV를 지원합니다. HWP는 PDF/HWPX로 변환해 첨부합니다.

AI 기본 모델은 gpt-6-astra, 추론 강도는 high입니다. 명시적인 AI 버튼에서만 API를 호출하고 `store=False`를 사용합니다. 요청 실패 시 기존 입력은 유지합니다. 자동 검사는 모델이 적은 모든 사실의 정확성이나 한컴의 최종 쪽 배치를 보증하지 않습니다.

## 주요 코드

- `app.py`: 한 화면 입력·AI 실행·DB 저장·다운로드
- `src/form_ui.py`, `src/form_examples.py`: 필드·표시 전용 예시
- `src/company_research.py`: 웹검색과 출처가 확인된 빈칸 병합
- `src/agent.py`, `src/document_prompt.txt`: 첨부 분석·요청 반영
- `src/application_store.py`: 서버 전용 DB 저장
- `src/download_ui.py`: 생성 후 같은 클릭에서 다운로드 시작
- `src/service.py`, `src/hwpx.py`, `src/product_list.py`: 문서 5종 생성

테스트는 API와 DB 호출을 대체하므로 실제 고객 자료를 수정하지 않습니다. 이전 로그인·암호 문서 관련 파일은 기존 자료 유지보수용이며 현재 앱 실행 경로에서 호출하지 않습니다.
