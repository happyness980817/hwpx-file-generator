# K-브랜드 신청서 도우미

회사·제품 자료 파일에서 AI가 정보를 추출해 필작성 서류 5종을 작성하는 **Python + Streamlit** 사이트입니다. 회원가입 없이 문서별 비밀번호로 이용합니다.

## 사용자 흐름

첫 화면에는 **K-브랜드 신청서 작성** 제목과 짧은 안내 아래 **새 문서 생성**, **작성한 문서 불러오기** 두 버튼이 있습니다.

### 새 문서

1. **새 문서 생성**을 누릅니다. 파일 첨부와 회사·상품 입력칸이 바로 표시됩니다.
2. 회사소개서·제품자료 등을 첨부하고 **자료로 자동 채우기**를 누릅니다. 요청사항은 **추가 요청**에서 입력합니다.
3. 노란색으로 표시된 미입력 칸을 확인합니다. 상품은 **상품 추가**, 수출국가는 드롭다운 복수 선택으로 지정합니다.
4. 문서 비밀번호를 정하고 **문서 생성**을 누르면 한글 4종과 엑셀 상품리스트를 개별 또는 ZIP으로 내려받습니다.

AI 없이도 화면에서 직접 입력할 수 있습니다. 회사명은 필수이며, 회사 추가 정보·상품 세부정보·활용계획은 접힌 영역에서 수정합니다. 링크 입력은 제거했습니다.

### 작성한 문서

**작성한 문서 불러오기 → 비밀번호 입력 → 불러오기**로 편집 화면을 엽니다. 작업번호·아이디는 필요하지 않습니다. 문서 생성과 수정 내용은 자동 저장되며, 저장에 실패하면 현재 내용을 유지하고 **다시 저장** 버튼을 표시합니다.

비밀번호는 문자와 숫자를 섞어 10~128자로 정합니다. 하나의 비밀번호는 하나의 작업에 대응하며, 이미 사용된 비밀번호로 새 문서를 만들면 다른 비밀번호를 입력하도록 안내합니다. 비밀번호를 아는 사람은 문서를 열 수 있으며, 분실 시 복구 기능은 없습니다. 비밀번호 발급·확인정보 다운로드 단계는 없습니다.

## 실행과 배포 설정

```powershell
uv sync --locked
uv run streamlit run app.py
```

브라우저: http://127.0.0.1:8501. `dev.cmd`는 로컬 주소에서 실행합니다.

`.env` 또는 Streamlit Cloud **Settings → Secrets**에 아래 이름으로 설정합니다. Cloud는 TOML 형식의 최상위 항목으로 입력합니다.

```toml
OPENAI_API_KEY = "실제 키"
OPENAI_MODEL = "gpt-6-astra"
OPENAI_REASONING_EFFORT = "high"
SUPABASE_URL = "https://YOUR_PROJECT_REF.supabase.co"
SUPABASE_SECRET_KEY = "실제 서버 Secret 키"
```

기존 `.env`를 덮어쓰지 마세요. 새 Supabase 프로젝트에서 보관함을 처음 준비할 때만 실행합니다.

```powershell
uv run python scripts/setup_guest_storage.py
```

이 명령은 비공개 `kbrand-guest-drafts` Storage 버킷만 준비합니다. Auth 계정, 로그인용 SQL, 공개 Storage 정책은 필요하지 않습니다. Publishable 키는 현재 문서 보관에 사용하지 않습니다. **문서 생성·불러오기에는 Storage 설정이 필요합니다.** AI 설정이 없으면 내용을 직접 입력해 저장·다운로드할 수 있습니다.

## 자료 분석과 모델

- 지원 파일: PDF, PNG/JPEG/WebP, DOCX, XLSX, PPTX, HWPX, TXT, CSV. HWP는 PDF/HWPX로 변환합니다.
- 파일당 10MB, 최대 5개, 합계 25MB입니다. 압축 문서는 압축 해제 크기도 검사합니다.
- PDF·사진은 글자와 이미지를 모델에 전달합니다. Word/Excel/PowerPoint/HWPX의 사진이 중요한 경우 PDF로 올립니다.
- 모델 기본값은 **gpt-6-astra**, 추론 강도는 **high**입니다. 기존 `.env` 또는 Streamlit Cloud Secrets에 `OPENAI_MODEL`이 있으면 그 값이 우선하므로, 배포 환경에서도 위 두 항목을 맞춥니다.
- 작성 규칙은 `src/document_prompt.txt`에서 관리합니다. 기존 입력 보존, 회사·브랜드·제조사 구분, 국가별 상표·수량 일치, 근거 없는 사실의 빈칸 처리, 실제 사실과 제안 문안의 구분을 요구합니다.
- 공개 회사·브랜드·상품 정보가 부족할 때 Responses API의 `web_search`로 보완합니다. 요청당 최대 4회이며, 공개 명칭·도메인으로만 검색하도록 지시합니다. 검색 도구 이용료와 추론 토큰 비용이 발생합니다.
- `store=False`로 호출하며 분석 실패·미완성 응답은 기존 입력에 적용하지 않습니다. 고급 모델과 엄격한 프롬프트도 무오류를 보장하지 않으므로, 사실관계와 노란 칸을 제출 전에 검토합니다.

## 문서 보관

- 신청서 내용, AI가 정리한 사실, 최근 대화, 확인 질문, 출처를 비밀번호 기반 AES-256-GCM으로 암호화해 비공개 Storage에 저장합니다. 비밀번호는 저장물에 포함하지 않습니다.
- 비밀번호에서 PBKDF2로 문서 위치를 계산해 `documents/` 아래에 보관합니다. 암호화에는 매번 무작위 salt·nonce를 사용하며, Supabase 키를 교체해도 기존 문서를 열 수 있습니다.
- 생성은 덮어쓰기를 금지한 업로드로 처리합니다. 기존 문서를 수정할 때는 먼저 복호화를 검증합니다. 잘못된 비밀번호는 다른 문서를 열거나 덮어쓰지 못합니다.
- **문서 생성**에서는 AI 실행 전에 빈 초안을 먼저 보관해 비밀번호 중복을 확인합니다. AI 실행에 실패해도 같은 비밀번호로 작업을 다시 열어 작성할 수 있습니다.
- 불러오기 시도는 IP별 분당 8회, 서버 프로세스 전체 분당 120회로 제한합니다. 제한 상태는 메모리에만 유지되며 여러 서버 간에는 공유하지 않습니다.
- 원본 업로드는 접속 세션의 메모리에서만 사용합니다. 생성 파일도 임시 폴더에서 검증한 뒤 다운로드 바이트만 남깁니다. 저장한 문서를 다시 열어 파일을 재생성할 수 있습니다.
- 원본 파일을 다시 분석하려면 다시 첨부합니다. 여러 창에서 같은 문서를 수정하면 마지막 저장 내용이 남습니다.

## 코드와 검사

```text
app.py                       첫 화면·비밀번호 입력·편집·다운로드
src/password_documents.py    비밀번호 기반 문서 찾기·중복 방지·접근 제한
src/guest_work.py            암호화와 Storage 연결, 이전 작업번호 API
src/agent.py                 자료 추출과 대화 수정
src/materials.py             파일 형식·크기 검사와 HWPX 텍스트 추출
src/document_prompt.txt       근거·정확성·항목별 작성 규칙
src/draft_schema.py          AI/수동 입력의 공통 데이터 구조
src/form_ui.py               회사·상품 입력칸과 복수 국가 선택
src/service.py               필작성 5종 생성과 ZIP 다운로드
src/hwpx.py                  원본 양식에 값 채우기·구조 검증
src/product_list.py          엑셀 상품리스트 작성
templates/                   HWPX 4종 + 엑셀 상품리스트 양식
scripts/setup_guest_storage.py  비공개 보관함 초기 설정
```

```powershell
uv run --locked pytest -q
```

자동 테스트는 실제 API·계정을 변경하지 않습니다. 화면 이동, 필수 비밀번호, 자동 저장·재시도, 비밀번호만으로 재열기, 중복·오입력·변조 거절, 세션 간 격리, 링크·파일 검사, AI 실패 시 내용 보존, 편집과 HWPX 생성을 검사합니다.

## 양식 범위

상품 최대 20개, 상품별 국가 최대 73개, 공장 최대 4개, 세부 제품 최대 50개입니다. 국가 선택지는 제공된 별첨의 73개국입니다. 국가별 상표·수량은 서로 구분해 유지합니다.

생성 파일은 제공된 [예시 폴더](https://drive.google.com/drive/u/0/folders/1YvQ4JDAaQUENjqKBkTORAqcRQRlBu-GY)의 필작성 양식을 기준으로 합니다.

1. [붙임1] 사용신청서와 상품별 세부정보 — 상품·국가 수에 따라 행과 별지를 확장합니다.
2. [붙임2] 도입 필요성 및 활용계획서
3. [붙임3] 확약서 및 제3자 정보제공동의서
4. [붙임4] 제3자 부당개입 배제 확약서
5. [붙임7] 상품리스트 — 예시의 상품 / No. / 세부 제품명 / 사양을 엑셀로 작성합니다.

HWP 원본은 개발 시 한컴으로 HWPX로 변환했고, 실행 시에는 Python ZIP/XML로 채웁니다. 서버에 Node·한컴 설치가 필요하지 않습니다. 빈 입력칸은 한글에서 노란 배경, 엑셀에서는 빈 셀 조건부 서식으로 표시합니다. 서명·직인·동의 및 제품사진은 자동 삽입하지 않습니다. 법적 확약 본문은 원문을 유지합니다.

기존 `LOGIN_SETUP.md`, `SUPABASE_SETUP.md`, `supabase/` SQL은 이전 로그인 설계 기록입니다. 현재 고객 사이트를 위해 실행할 필요가 없습니다. 이전 작업번호 API는 코드에 남아 있지만 현재 화면에서는 사용하지 않습니다.

UX 참고: [Smallpdf](https://smallpdf.com/edit-pdf), [SimplePDF](https://simplepdf.com/)의 자료 선택 후 편집 흐름을 참고해 입력·설정 설명을 줄였습니다.
